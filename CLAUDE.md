# PROHVAC — заметки для Claude Code

## Тестирование форм в Playwright

**Не использовать реальные имена, телефоны, email и другие настоящие данные
в тестах и скриптах Playwright.** Только заведомо тестовые значения.

Форма заявки отправляет данные в реальный Telegram-чат отдела продаж, поэтому
запуск теста с настоящими данными создаёт живую заявку и засоряет рабочий чат.

Использовать:

- имя — `Тест Тестов`, `Test User`;
- телефон — `+998 90 000 00 00` (проходит валидацию `^998\d{9}$`);
- сообщение — `Тестовая заявка, игнорировать`.

Перед прогоном, который реально доходит до отправки, убеждаться, что
`TELEGRAM_BOT_TOKEN` в окружении не боевой либо что `TELEGRAM_API_BASE`
указывает на заглушку. В `npm run dev` обработчик заявок исполняется
по-настоящему: dev-сервер поднимает тот же роутер, что и прод, — то есть
заявка из теста дойдёт ровно туда, куда настроен бот.

## Почему «локально всё отправилось», а в чате пусто

`TELEGRAM_API_BASE` перенаправляет ВСЕ исходящие вызовы Bot API. Пока
переменная указывает на `scripts/mock-telegram.mjs`, заявка получает статус
`sent`, форма показывает «спасибо», кнопка «проверить» в админке отвечает
успехом — и ни одно сообщение не уходит в Telegram. Это не сбой, а ровно то,
о чём переменная и просит.

Что с этим сделано, чтобы ошибка больше не была бесшумной:

- на каждом старте печатается предупреждение, если адрес не
  `https://api.telegram.org` (раньше проверка работала только при
  `NODE_ENV=production`);
- кнопка «Отправить тестовое сообщение» при подменённом адресе отвечает
  ОТКАЗОМ, а не успехом: «успех» здесь означал бы, что сообщение видно
  в рабочем чате;
- заглушка проверяет то же, что и настоящий API: формат токена, chat_id,
  разметку MarkdownV2 и предел в 4096 символов. Локальный успех теперь
  что-то значит.

**В проде `TELEGRAM_API_BASE` не задавать.** Если заявки не доходят —
сначала посмотреть эту переменную, потом всё остальное.

## Кнопки статуса в чате (CRM)

Карточка заявки уходит с inline-клавиатурой: «Новая», «В работе»,
«Обработана», «Спам». Нажатие меняет статус заявки в базе, карточка
перерисовывается с галкой у выбранного статуса, а в админке у заявки
появляется пометка «статус из Telegram (@кто)».

- `server/domain/lead-crm.js` — кодирование `callback_data` и клавиатура.
  Значение подписано HMAC от `APP_SECRET`: без подписи любой участник чата
  мог бы выставить статус произвольной заявке, подменив номер в запросе.
- `server/application/telegram-crm.js` — применение нажатия и `WEBHOOK_PATH`.
- `server/routes/public.telegram.js` — `POST /api/telegram/webhook`. Это
  единственный неаутентифицированный пишущий адрес: подлинность даёт заголовок
  `X-Telegram-Bot-Api-Secret-Token`, неверный секрет отвечает тем же
  `uniform404`, что и любой несуществующий путь.
- Подключается кнопкой «Подключить кнопки статуса» в настройках. Нужен
  `PUBLIC_ORIGIN` на https — Telegram не ходит ни по http, ни на loopback.

Новых статусов CRM не вводит: четыре кнопки ложатся ровно на `CHECK` таблицы
`leads`. Расширять этот `CHECK` в STRICT-таблице значит перестраивать таблицу
с персональными данными целиком — ради ярлыка в чате оно того не стоит.

Ротация `APP_SECRET` обесценивает кнопки на уже отправленных карточках: они
ответят «Кнопка устарела». Это осознанно — подпись не должна переживать смену
ключа.

## Аналитика включается флагом

`ANALYTICS_ENABLED` по умолчанию **выключен**, и при выключенном флаге счётчик
вырезается из HTML целиком, а домены Яндекса не попадают в CSP. На проде без
`ANALYTICS_ENABLED=1` аналитики нет вообще. Проверяется одной командой:
`curl -sH 'Accept: text/html' https://<домен>/ | grep -c mc.yandex.ru`.

Dev-сервер счётчик вырезает ВСЕГДА (плагин `analytics-dev-strip` в
`vite.config.js`): иначе каждый `npm run dev` слал бы просмотры в боевой
счётчик, а Вебвизор записывал бы локальную админку.

## Структура

- `server/routes/public.lead.js` accepts a lead: validation, rate limit, write.
  Delivery lives in `server/application/lead-delivery.js` and the Bot API call
  in `server/integrations/telegram.js`; the route holds no token.
- `server/application/telegram-config.js` resolves the bot token and chat id.
  A value stored in the database settings (encrypted with `APP_SECRET`) beats
  the environment variable. No secret may reach the client bundle.
- `server/app.js` — продовый роутер, точка входа `handleRequest(req, res, next)`.
- `shared/lead.js` — общие правила валидации для клиента и сервера.
  При изменении правил править здесь, а не в двух местах.
- `shared/lead.test.js` — тесты валидации и экранирования, `npm test`.
- `src/index.css` — дизайн-система лендинга, классы `pv-*`.

## Локальная работа формы

Плагин `api-dev` из `vite.config.js` поднимает в dev-сервере **продовый
роутер** `server/app.js`, а не отдельную копию обработчика: `/api/*`,
`/locales/*` и `/media/*` обслуживает тот же код, что и на хостинге,
поэтому dev и прод не расходятся. Остальное (страницу, модули из `src`,
файлы из `public`) по-прежнему отдаёт Vite — иначе вместо HMR браузер
получал бы прошлую сборку из `dist`.

Схему в базе плагин накатывает сам, перед первым запросом к серверным
маршрутам (в проде это делает `server/index.js` до `listen`). База и медиа
лежат в `DATA_DIR` (по умолчанию `./data`, в git не попадает).

Порядок запуска — одна команда:

```
npm start
```

Она поднимает заглушку Bot API и dev-сервер вместе, гасит оба по Ctrl+C и,
главное, отказывается стартовать, если `TELEGRAM_API_BASE` пуст или указывает
не на локальный адрес: иначе первая же тестовая заявка ушла бы в рабочий чат.

Раздельный запуск остался для отладки: `npm run mock:telegram` и `npm run dev`.

`.env.local` (в git не попадает) по умолчанию указывает
`TELEGRAM_API_BASE=http://127.0.0.1:8788`, то есть локально заявки уходят
в заглушку, а не в рабочий чат. **В проде `TELEGRAM_API_BASE` не задавать.**

Если Vite после обновления версии падает с `__WS_TOKEN__ is not defined` —
удалить `node_modules/.vite` и перезапустить: это устаревший кэш dev-клиента.

## Команды

- `npm start` — заглушка Telegram и dev-сервер одной командой (обычный путь).
- `npm run dev` — только Vite dev-сервер (вместе с продовым роутером `server/app.js`).
- `npm run smoke:telegram` — сквозная проверка заявки: HTTP → SQLite → Telegram.
- `npm run prepare:production` — секреты для панели хостинга и проверка конфига.
- `npm run verify:live -- https://www.prohvac.uz` — проверка БОЕВОГО сайта после
  выкладки: заголовки, счётчик, маскировка админки, вебхук Telegram. Только
  читает: заявок не отправляет, в чат не пишет. С `TELEGRAM_BOT_TOKEN`
  в окружении дополнительно спрашивает у Telegram, зарегистрирован ли вебхук.
- `npm run mock:telegram` — заглушка Telegram Bot API.
- `npm run lint` / `npm test` / `npm run build` — должны проходить без ошибок.
- `npm run optimize:images -- <src> <out>` — конвертация ассетов в WebP.

## Аналитика

Счётчик Яндекс.Метрики стоит инлайном в `index.html` с `nonce="__CSP_NONCE__"`
и отдаётся ТОЛЬКО публичной страницей — через `sendPublicShell()` из
`server/http/spa.js`. Обычный `sendSpa()` счётчик вырезает всегда.

Так сделано намеренно: оболочка в проекте одна на публичную страницу, админку
на секретном пути и на каждый `uniform404`. Счётчик в оболочке админки отправил
бы `ADMIN_SECRET_PATH` в отчёты Метрики, а Вебвизор записал бы саму панель —
заявки с именами и телефонами, привязку TOTP, поля настроек.

Добавляя новый публичный маршрут, отдающий оболочку, используйте
`sendPublicShell()`; сторожевой тест в `server/http/spa.test.js` фиксирует, что
таких вызовов ровно два.

Поля формы заявки помечены классом `ym-hide-content` — без него Вебвизор
записывает имя и телефон. В настройках счётчика запись всех полей должна быть
выключена.

Дашборд «Аналитика» в админке ходит в Stat API через сервер
(`server/routes/admin.analytics.js`), а не из браузера: OAuth-токен не покидает
сервер, да и `connect-src` в CSP не пустил бы панель на сторонний адрес.
Ответы кэшируются в `metrica_cache`; просроченная запись НЕ мусор — она
показывается с пометкой «данные от…», когда Яндекс недоступен.

Цели ищутся по имени из `shared/analytics.js`, а не по числовому id: id
в коде показывал бы нули после пересоздания цели в интерфейсе Метрики.
