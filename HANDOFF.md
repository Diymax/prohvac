# PROHVAC — передача разработчику

Лендинг с админ-панелью. Фронтенд — Vite + React 18, бэкенд — Node **без единой
рантайм-зависимости** (`node:http`, `node:sqlite`, `node:crypto`).

## Быстрый старт

```bash
npm ci
cp .env.example .env.local          # заполнять не обязательно: локально подставятся дев-заглушки
npm run mock:telegram               # терминал 1 — заглушка Bot API на 127.0.0.1:8788
npm run dev                         # терминал 2 — сайт на http://localhost:5173
```

Схема базы накатывается сама перед первым обращением к `/api/*`. База и медиа
лежат в `DATA_DIR` (по умолчанию `./data`, в git не попадает).

Наполнить контентом и создать администратора:

```bash
node --experimental-sqlite scripts/seed-content.mjs
node --experimental-sqlite scripts/admin-cli.mjs create-user --username admin --role owner
```

Пароль печатается один раз. Вход в панель локально — `http://localhost:5173/dev-insecure-admin-console`
(в проде адрес задаётся `ADMIN_SECRET_PATH`).

> **Node 22.13+** — ниже этой версии `node:sqlite` требует флага
> `NODE_OPTIONS=--experimental-sqlite`. Драйвер выдаёт внятную ошибку с подсказкой.

## Проверки

```bash
npm run lint     # 0 ошибок обязательно: --max-warnings 0
npm test         # 333 теста
npm run build    # сборка
npm run gc       # уборка базы по требованию (сервер делает её сам, раз в сутки)
```

## Архитектура

```
app.cjs                 точка входа Passenger (CJS-шим: проект на ESM)
server/
  index.js              listen, миграции, периодический проход очереди перевода
  app.js                конвейер запроса: нормализация → заголовки → гейт → маршруты
  config.js             валидация окружения, падает на старте при пустых секретах в проде
  http/                 respond, static, spa, body, cookies, multipart
  auth/                 password (scrypt), session, csrf, guard, totp, base32, gate, throttle
  crypto/               secretbox (AES-256-GCM), hashid (HMAC от IP и UA)
  db/                   драйвер node:sqlite, миграции, раннер
  routes/               public.lead, public.content, admin.*
  translate/            провайдеры, реестр, очередь, защита терминов
  lib/                  image (валидация по сигнатуре), ratelimit, timing
shared/lead.js          правила валидации заявки — общие для клиента и сервера
src/                    лендинг; src/admin/** — панель, отдельный ленивый чанк
scripts/                admin-cli, seed-content, mock-telegram, optimize-images, build-release
```

### Решения, которые стоит знать до правок

**Ноль рантайм-зависимостей.** Хостинг даёт 500 МБ на всё, и 317 из них уже
однажды съел закоммиченный `node_modules`. Express не нужен, а его умолчания
(`X-Powered-By`, `Cannot GET /path` в теле 404) сами по себе выдают админку сканеру.

**Всё разделяемое состояние — в SQLite.** Passenger держит пул процессов:
лимитер в памяти считал бы окно у каждого своё, то есть «5 заявок в минуту»
умножалось бы на число процессов.

**Маскировка админки.** `/admin`, несуществующий путь и honeypot отдают
байт-в-байт одинаковый ответ; `/api/admin/*` без гейта неотличим от неизвестного
`/api/*`. Любая правка, вносящая разницу в статус, длину тела или заголовки,
ломает защиту целиком — это проверяется тестом.

**Второй фактор обязателен на сервере, а не в интерфейсе.** Сессия без
подтверждённого TOTP не отдаёт ни заявок, ни контента.

**Уборка базы идёт сама.** `server/lib/maintenance.js` вызывается таймером
из `server/index.js`; право на проход разыгрывается через `app_state.last_purge_at`,
поэтому в пуле процессов работу берёт ровно один и не чаще раза в сутки.
Это не оптимизация диска: `leads.purge_after` — срок хранения персональных
данных, и наступать он обязан без чьей-либо команды. Ту же функцию зовёт
`npm run gc`, когда нужно прибрать прямо сейчас.

**Антибрут по адресу подключён к маршруту входа.** `server/auth/throttle.js`
считает неудачи, ловит перебор списка логинов и банит адрес в `ip_blocks`.
Ответ входа при этом не меняется никогда: отдельный код на «адрес забанен»
подсказал бы перебирающему сам порог. Блокировка проявляется на следующем
запросе, в `dispatch`, и выглядит как обычный несуществующий путь.

**Пароль проверяется не только по длине.** `validatePasswordStrength` отвергает
клавиатурные ряды, повторы, словарные варианты и требует три класса символов.
Проверка выполняется и при входе: пароль, который перестал отвечать правилам,
поднимает `must_change_password`, и панель до смены не открывается.

**Ручные переводы не перетираются.** Правка русского помечает их устаревшими,
но в очередь не ставит: тихая перезапись человеческой корректуры машинным
переводом необратима.

## Что осталось нерешённым

Все пункты подтверждены чтением кода, ни один не блокирует запуск.

1. **`X-Real-IP` принимается без списка доверенных прокси.** На штатной связке
   Plesk + nginx заголовок перезаписывается и всё корректно. При прямом запуске
   или другом прокси клиент подставит произвольное значение и обойдёт лимит
   заявок и блокировки. Нужен `TRUST_PROXY_HEADERS` в `config.js` и один общий
   `clientIp` вместо четырёх копий.
2. **Сессия не сверяется с User-Agent.** `sessions.ua_hash` пишется и переносится
   при ротации, причина ревокации `ip_change` объявлена, но сравнения нет.
3. **Часть настроек панели ни на что не влияет:** `media.quota_bytes`,
   `lead.rate_max`, `lead.rate_window_ms` читаются из окружения и констант;
   `form.require_message` не читается вовсе.
4. **Ошибка чтения БД неотличима от пустой таблицы** в `public.content.js`:
   секундный `SQLITE_BUSY` приведёт к отдаче сборочных локалей, и результат
   закэшируется. Нужно возвращать `null` вместо пустого массива.
5. **Заявка пишется в журнал до проверки лимита** — отбитый 429-м флуд всё равно
   оставляет строки с ПДн.
6. **`ключ DeepL` из панели не читается провайдером:** настройка называется
   `deepl.api_key`, а провайдер ищет `translation.deepl.key`.
7. **Мелочи:** `amr` пишется то через запятую, то через плюс; `isSet` для
   секретов всегда `false` (проверяется `value` вместо `value_ct`);
   `formatPhone` рассчитан ровно на 12 цифр; оба canvas пересоздают частицы
   на каждый `resize` без дебаунса.
8. **Не покрыто тестами то, где ломалось чаще всего** — стыки модулей. Полезно
   добавить контрактный набор: перебор всех вызовов `api.*` против
   зарегистрированных маршрутов и прогон очереди перевода через реальный адаптер.
9. **Требование сменить пароль держится на клиенте.** Сервер помечает учётку
   (`must_change_password`) и панель до смены не открывается, но остальные
   маршруты `/api/admin/*` такой сессии по-прежнему отвечают. Закрывается
   проверкой в общих `authorize()` четырёх файлов маршрутов.

## Что закрыто 29.07.2026

Аудит и правки одной сессией, подробности — `.claude/plans/2026-07-29-security-audit-and-frontend-fixes.md`.

- Модуль антибрута `server/auth/throttle.js` не вызывался ниоткуда, кроме
  ловушки для сканеров: перебор списка логинов не детектировался, `ip_blocks`
  по `login_bruteforce` не заполнялся никогда.
- Уборка `gc` существовала только командой CLI, то есть срок хранения ПДн
  не наступал, а `rate_limit`, `login_attempts` и `audit_log` росли бессрочно.
- Ведро лимитера по логину заводилось до проверки лимита по адресу — поток
  уникальных логинов растил таблицу неаутентифицированными запросами.
- **Формы смены пароля не существовало вовсе:** `POST /api/admin/password`
  не вызывался ни из одного экрана, и предупреждение «смените временный
  пароль» было невыполнимым.
- Картинки привязывались вводом номера файла руками — добавлен выбор
  из библиотеки.
- Арабская локаль: герой не зеркалился (inline-transform параллакса затирал
  правило), лента партнёров крутилась в пустоту, арабского шрифта не было.
- Сетки проектов, «о компании» и контактов обрезались на экранах 320-360px.
- Ссылки подвала имели тач-таргет 18-20px.
- Контрасты кнопок и служебного текста не дотягивали до WCAG AA.
- **Первичная привязка 2FA срывалась по таймауту.** Промежуточная сессия жила
  пять минут и не продлевалась, а на этой стадии человек ещё только ставит
  приложение-аутентификатор. Окно истекало, `POST /api/admin/2fa/confirm`
  отвечал `uniform404`, и панель молча возвращала на форму входа — снаружи
  выглядело как «привязка не работает». Теперь стадия без подтверждённого
  секрета живёт 20 минут (`ENROLL_TTL_MS`), на экране написано про лимит,
  а потеря сессии показывает причину, а не пустую форму входа.

## Деплой

`npm run build:release` собирает архив и `release/DEPLOY.md` с пошаговой
инструкцией. Ключевое:

- на сервере занято ~497 МБ из 500, сначала удалить старый `node_modules`;
- `DATA_DIR` вынести **за пределы** `httpdocs`, иначе база с сессиями и заявками
  начнёт раздаваться по HTTP;
- `TELEGRAM_API_BASE` в проде **не задавать** — с ним заявки уходят в заглушку;
- `APP_SECRET` и `GATE_SECRET` должны различаться;
- `ADMIN_SECRET_PATH` — минимум 24 случайных символа, иначе процесс не поднимется.

После выкладки обязательна проверка:

```bash
curl -I https://домен/admin
curl -I https://домен/nonexistent-xyz
```

Ответы обязаны совпасть до заголовка.

## Чего в архиве нет

`node_modules`, `dist`, `data/` (база с ПДн), `.env.local` (секреты), `release/`.
Токен бота и chat_id получить у заказчика и задать в окружении.
